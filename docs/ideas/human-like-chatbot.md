# 拟人化聊天机器人 — Human-like Chatbot

## Problem Statement

如何构建一个部署在即时通讯平台（QQ优先、后续跨平台）上、行为高度拟人、人格可定制、且能通过数据训练和个人对话逐步演化的聊天机器人？

## Recommended Direction

### 拟人中间件架构（Human-like Middleware）

核心思路：**不在模型层面做深度改造，而在 LLM API 外围封装一层「拟人化中间件」**，由中间件控制所有与"人"相关的行为特征。

```
用户 ──→ 平台适配层（QQ/微信/Discord）
               │
               ↓
        ┌──────────────────┐
        │  拟人化中间件      │
        │  ┌──────────────┐ │
        │  │ 人格引擎      │ │ ← 管理性格特征、知识偏好、情绪状态
        │  │ 行为调度器    │ │ ← 控制打字延迟、发送节奏、作息
        │  │ 记忆系统      │ │ ← 短期记忆（上下文）+ 长期记忆（持久化）
        │  │ 演化引擎      │ │ ← 根据时间/事件推动性格渐变
        │  └──────────────┘ │
        └──────────────────┘
               │
               ↓
        LLM API（云端：DeepSeek/OpenAI → 后续本地：Qwen/ChatGLM）
```

### 核心架构模块

#### 1. 人格引擎（Personality Engine）
- **性格特征配置**：一组可调节的维度（开放度、幽默感、直率程度、话题偏好等）
- **知识偏好**：向量化的知识库，RAG检索注入上下文
- **情绪模型**：对话上下文影响情绪状态，情绪影响表达方式
- **个人数据注入**：通过 LoRA 微调或 Few-shot Prompting 注入个人语言特征

#### 2. 行为调度器（Behavior Scheduler）
- **打字状态模拟**：随机延迟（150ms-3s），长回复前显示"正在输入"
- **发送节奏控制**：大段回复分段发送，模拟人"边想边打"
- **作息规律**：配置活跃时段（如 8:00-23:00），非活跃时段降低回复频率或告知"在忙"
- **错别字/口语化**：偶尔加入语气词、口语表达，甚至合理的小错误

#### 3. 记忆系统（Memory System）
- **短期记忆**：对话窗口内上下文（LLM本身的 context window）
- **长期记忆**：重要事实、用户偏好、过往话题摘要，使用向量数据库（Chroma/Qdrant）持久化
- **记忆回放**：定期回顾和总结过去对话，模拟人的"回忆"过程

#### 4. 演化引擎（Evolution Engine）⭐ 核心亮点
- **时间驱动**：性格特征随时间缓慢漂移（比如越来越熟悉后会变得更随意）
- **事件驱动**：共同经历的事件（如某次深入对话）会导致性格微调
- **学习驱动**：从用户的表达习惯中学习，逐步趋同（镜像效应）
- **演化幅度控制**：变化是渐变而非突变，保持人格一致性

### 技术栈建议

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| QQ接入 | NapCat / LLOneBot | 社区成熟QQ机器人框架 |
| 跨平台抽象 | Python ABC（抽象基类） | 定义统一的 Message/Event 接口 |
| LLM API | DeepSeek API（初期） | 性价比高，中文能力强 |
| 本地模型 | Qwen2.5 / ChatGLM4（后期） | 条件具备后迁移 |
| 向量数据库 | ChromaDB（轻量） | 本地运行，无需独立服务 |
| 记忆存储 | SQLite + ChromaDB | 关系型存结构化数据，向量库存语义 |
| 微调框架 | Unsloth / LoRA | 轻量级微调，消费级GPU可用 |
| 主语言 | Python | LLM/NLP生态最成熟 |

## Key Assumptions to Validate

- [ ] QQ 机器人框架当前可用且稳定（NapCat/LLOneBot 状态确认）
- [ ] DeepSeek API 延迟和成本在可接受范围内
- [ ] 个人聊天数据可以合法获取用于训练（建议仅使用自己的数据）
- [ ] 拟人中间件架构能提供足够真实的拟人体验
- [ ] 演化引擎在不破坏人格一致性的前提下产生有意义的性格变化

## MVP Scope

**第一阶段 — 核心骨架（2-4周）**
- [ ] QQ 平台接入（NapCat + Python SDK）
- [ ] 基础拟人中间件：打字延迟 + 发送节奏 + 作息控制
- [ ] 人格引擎 v1：可配置的性格维度 + 情绪模型
- [ ] 接入 DeepSeek API，基础对话可用
- [ ] 使用公开的中文人设数据集测试

**第二阶段 — 人格深化（4-6周）**
- [ ] 长期记忆系统（ChromaDB）
- [ ] 个人数据导入工具（聊天记录解析 → 性格特征提取）
- [ ] 演化引擎 v1：时间驱动的性格渐变
- [ ] 跨平台抽象层，接入第二个平台（如 Discord）

**第三阶段 — 进阶能力（6-8周）**
- [ ] 本地模型部署（Qwen2.5 4bit 量化）
- [ ] LoRA 微调管线，用个人数据微调
- [ ] 事件驱动的性格演化
- [ ] 渐进学习：从对话中自动提炼特征

## Not Doing (and Why)

| 不做 | 原因 |
|------|------|
| ❌ 角色市集/平台化 | 过早，先验证核心价值 |
| ❌ 端到端模型微调替代中间件 | 成本高、迭代慢，中间件更灵活 |
| ❌ 语音/多模态 | 大幅增加复杂度，第一期聚焦文本 |
| ❌ 自建 QQ 协议 | 使用社区成熟方案，专注上层逻辑 |
| ❌ 移动端 App | CLI + 后台服务即可，后续再说 |

## Open Questions

1. **QQ机器人封号风险**：NapCat 等方案的具体风险等级？是否有官方白名单渠道？
2. **数据隐私**：用户聊天数据导入后的安全存储方案？是否全本地处理？
3. **演化可控性**：用户是否需要在某个时刻"冻结"性格？演化幅度如何量化？
4. **拟人度评估**：怎么衡量"像不像人"？是否有客观指标（图灵测试变体）？
5. **个人数据量下限**：多少聊天记录才足以提取有意义的性格特征？
